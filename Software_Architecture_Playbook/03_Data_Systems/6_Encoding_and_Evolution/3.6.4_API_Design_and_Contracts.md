### How is a service API defined?
<details><summary>Show answer</summary>

A client must know each endpoint, what to send and what comes back.
An [IDL](#what-is-an-idl-and-what-does-it-give) (interface definition language) writes this down in one file.

</details>

### What is an IDL, and what does it give?
<details><summary>Show answer</summary>

An IDL (interface definition language) describes an API in a file that doesn't belong to any programming language:
each endpoint or method, what it takes, what it returns, and the type of every field. Server and clients both work
from this file, so it is the contract between them.

From the one file, tools build:
- **Breaking-change checks** — CI compares the changed file with the last released one (`oasdiff breaking`,
  `buf breaking`), so a change that breaks backward or forward compatibility fails the build before it ships.
- **Client libraries** — generated for many languages (`openapi-generator`, `protoc`) instead of hand-written, so
  every client matches the API exactly.
- **Docs** — built from the file (Swagger UI, Redoc), so they change when the file changes and can't go out of date.

</details>

### Which IDL for which kind of API?
<details><summary>Show answer</summary>

- **REST/HTTP with JSON** — OpenAPI (YAML or JSON file).
  Its old name is Swagger; today Swagger names the tools around it (Swagger UI, Swagger Editor).
  Older rivals: RAML, API Blueprint — mostly replaced by OpenAPI.
- **RPC** — [Protocol Buffers](3.6.2_Encoding_Formats.md#what-are-protocol-buffers) (`.proto`) for gRPC;
  Thrift (`.thrift`).
- **Messages and events** — Avro schemas (`.avsc`, or the shorter Avro IDL `.avdl`), also Protobuf.
  AsyncAPI describes whole event APIs: channels, topics and the messages on them.
- **GraphQL** — its own schema language (SDL).
- **SOAP** — WSDL (XML), the older generation.

</details>

### Working with an IDL — what are the ways?
<details><summary>Show answer</summary>

- **Code-first** — write the code; a tool [builds the IDL file from it](#openapi-file-from-java-code--how).
- **Contract-first** (also design-first, API-first) — write the IDL file first; generate server interfaces and clients
  from it, then implement the interfaces.

</details>

### Code-first vs contract-first — when which?
<details><summary>Show answer</summary>

Root: what is written first — the server code or the [IDL](#how-is-a-service-api-defined) file.

- **Code-first** — write the server; the framework generates the IDL from the code (FastAPI).
    - Prefer for: an internal API where one team owns the server and its clients, and changes are frequent.
    - Cost: the contract is a side effect — a refactoring can change the API without anyone noticing; clients
      wait until the server exists.
- **Contract-first** — write the IDL; generate server stubs and clients from it (gRPC).
    - Prefer for: APIs used by other teams or companies. Teams agree on the file, then build server and clients in
      parallel, and every API change is reviewed as a change to the file.
    - Cost: an extra file and tools to maintain, and the server must fit the generated stubs.

</details>

### OpenAPI file from Java code — how?
<details><summary>Show answer</summary>

A tool reads the REST annotations in the code and builds the OpenAPI file from them. The code comes first; the file is
the output.

- **springdoc-openapi** — Spring Boot. Inspects the running app (Spring MVC/WebFlux annotations, class structure) and
  serves the file at `/v3/api-docs`, with Swagger UI at `/swagger-ui.html`. Extra detail comes from Swagger
  annotations (`@Operation`, `@Schema`).
- **MicroProfile OpenAPI** — Jakarta REST (JAX-RS). A spec, not a library: the server builds the file from the JAX-RS
  annotations and serves it at `/openapi`; MicroProfile `@Operation`, `@APIResponses` add detail. Supported by
  Quarkus, WildFly and Open Liberty; SmallRye OpenAPI is the implementation in Quarkus and WildFly.
- **Enunciate** — JAX-RS and Spring MVC, at build time through a Maven plugin. Takes descriptions from Javadoc and
  writes the OpenAPI file, HTML docs and client libraries.

</details>
