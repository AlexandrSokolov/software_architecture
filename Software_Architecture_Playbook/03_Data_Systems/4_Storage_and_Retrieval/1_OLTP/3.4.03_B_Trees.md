## 3.4.3 B-Trees

Book: B-Trees (125–128).

Holds:
- Pages: fixed-size blocks on disk, arranged as a tree. Branching factor = how many child pointers one page holds.
- Lookup: walk from the root page to a leaf page; why 3–4 levels are enough.
- Writes: overwrite the page in place; split the page when it is full.
- Crash safety: what the WAL protects here (a half-done page split).
- Many threads at once: short locks on pages (latches).
- Variants: copy-on-write (write a new page instead of overwriting), shortened keys, pointers to neighbour pages.

Not here: what a WAL is (3.4.2), write amplification (3.4.4).

B-tree

This is the classic engine, used by almost every relational database (PostgreSQL, MySQL, Oracle). It does the opposite of the LSM-tree:

Data lives on disk in fixed-size blocks called pages, a few KB each, arranged as a tree.
Each page holds keys and pointers to child pages. To find a key, you walk from the root page down to a leaf. Three or four levels are enough for most databases.
Writes overwrite the page in place. When a page is full, it splits into two.
If the database crashes in the middle of a split, the tree is broken. So B-trees also use a WAL: write the change to the log first, then change the page.
