## 3.4.1 Why Indexes

Book: Ch. 4 — Storage and Indexing for OLTP (116), start of Log-Structured Storage (118).

Holds:
- Chapter router: links to every 3.4.x file, plus the chapter thread:
  log = fast write, slow read → an index trades write speed for read speed → two engines (LSM, B-tree)
  → compare them → design the index for the query → or keep everything in memory.
- The simplest database: append every write to the end of one file. Fastest write; a read scans the whole file.
- What an index is: an extra structure, built from the data, that tells you where a key is.
- The cost: every write must also update the index, so the database doesn't index everything — you choose.

Not here: how indexes are built (3.4.2, 3.4.3), which columns to index (3.4.5).
