## 3.4.2 LSM-Trees

Book: Log-Structured Storage (118–124).

Holds one chain, in order — each step fixes the problem of the step before:
- Hash index over the log: key → byte position in the file, kept in memory.
- Segments and compaction: cut the file into pieces, merge them in the background, keep the latest value per key.
  Deleting a key: a tombstone — a special record meaning "this key is deleted".
- SSTable: segments sorted by key. Only some keys in memory, range queries work, merging is cheap.
- Memtable: a sorted tree in memory; when it gets big, written to disk as one SSTable.
- WAL: the concept card lives here (first place you meet it). Here it protects the memtable from a crash.
- LSM-tree: the name for the whole design — memtable + SSTables on disk + background merging.
- Bloom filter: skips files that cannot hold the key.
- Compaction strategies: size-tiered vs leveled.

Not here: write amplification (3.4.4).
