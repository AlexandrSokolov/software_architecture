### What is the document model?
<details><summary>Show answer</summary>

Data is stored as **documents**, usually JSON. A document holds a whole record with its nested parts. 
For example, a user profile keeps its list of jobs and schools inside it, not in separate tables.

So one document is a tree. Documents are grouped into **collections** (≈ tables in SQL).

</details>

### Do document databases normalize data?
<details><summary>Show answer</summary>

They can store both, but they usually lean to **denormalized** data. 
Example: an order document keeps a copy of the customer's name, not only a `customer_id`.

Two reasons:
- **Copies are easy** — JSON makes it simple to add one more copied field.
- **Joins are weak** — many document databases support joins poorly, so following IDs is inconvenient.

</details>
