From DeBrie (DynamoDB) and Cassandra practice. DDIA Ch. 3 has no section on it:

Structure: partition key + sort key, rows with the same partition key sit together and are sorted, so you can read a range inside one partition
Query-first design: you start from the queries, not the entities, because there are no joins
Single table design: several entity types in one table, with generic key names (PK, SK), so a parent and its children come back in one query
Duplicating data on purpose: one copy per access pattern, and you update all of them on a write
Partition key choice: high-cardinality keys, and why a hot or ever-growing partition hurts
The name trap: wide-column is not column-oriented storage (Parquet, warehouses). DDIA warns about this confusion, so interviewers can ask it.
