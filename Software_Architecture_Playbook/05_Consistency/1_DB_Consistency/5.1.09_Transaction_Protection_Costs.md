# Transaction Protection Costs

The price of keeping data consistent. Every protection from the problems file costs something: locks make
transactions wait and can deadlock, optimistic checks and serializable make them fail and retry, a retry repeats
whatever the transaction did outside the database, and a long transaction holds locks, a connection and old row
versions the whole time.

This file covers how these costs show up, how to handle them, and how to keep them small: deadlocks, retries, side
effects, remote calls inside a transaction, and long transactions.
