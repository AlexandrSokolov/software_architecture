## 3. Interview order

Tuned for the senior Java developer role first. Architect notes at the end. This order is the plan and changes with
the role; the folder numbers above are the map and stay fixed.

Data moving between systems (`05_`) comes before one database on many machines (`04_`): the first is daily work, the
second has no hands-on practice yet. A few sections from `04_` chapters are pulled forward because calls between
systems need them: partial failure and timeouts (Ch. 9), one commit across systems (Ch. 8), the change log that CDC
reads (Ch. 6).

**Architect override:** if an architect interview gets scheduled early, move #15 to #2, right after Ch. 2. It gives
the vocabulary for high-level trade-offs before the low-level mechanics.

**System design override:** if a system design round gets scheduled before #12, read these first: Problems with
Replication Lag (209), Solutions for Replication Lag (214), Sharding by Key Range (256) vs by Hash of Key (258),
Skewed Workloads and Relieving Hot Spots (263). Read replicas and sharding come up in almost every "how does this
scale" question.
